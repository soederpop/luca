The way it works today

Every app starts with a pile of strangers.

Ask a coding agent for an app today. Its first move is to download hundreds of packages written by people you will never meet.

Then it invents its own patterns. Its own way to store data, its own way to talk to a server, its own folder layout. Again, from zero, for every project.

To keep that from turning into a mess, you need the smartest, most expensive model there is. And you still cannot see what it put on your machine.

3
The way it adds up

Ten apps. Ten ways of doing everything.

Vibe code one app and you get a pile. Vibe code ten and you get ten piles, each built its own way.

One stores dates as text, the next as numbers. One logs people in with tokens, the next with cookies. One talks JSON over REST, the next invented its own format. Nothing fits anything else.

So you ask an AI to cram them together. Every join it writes is new code that nobody tested, and a new place for a mistake to hide. The mess does not get smaller. It grows at the seams.

4
The idea

Give the agent a box of bricks.

A kid with a box of bricks never has to design the tab that holds them together.

Reuse, standard sizes, the way every piece fits every other piece: all of that is solved inside the brick. The kid only brings the idea. That is why one box can become a castle, a ship, or a city.

Luca gives your coding agent the same deal. The hard design problems are already decided in the parts. The agent does not need genius. It needs to snap pieces together, and it can.

Unlimited creativity. Safety through constraints.

The builder

An agent that knows every part.

Every component comes with its own instructions. Luca's agent reads them before it builds, so it never guesses how a part works.

Use Luca as your coding agent. Or use it as the foreman for the agents you already pay for: Claude Code, Codex, Hermes. Hand each one a task file. Run them side by side.

The instructions are the same ones you read. Ask the CLI about any of them and it answers.

See the CLI

terminal 
# talk to the agent in your project
luca chat

# read the instructions on any component
luca describe scheduler

# send a task to an agent you already have
luca prompt claude tasks/add-billing.md

# or run several at once, side by side
luca prompt codex tasks/*.md --parallel

Build your own agents

An agent is a folder and a markdown file.

Write down who the agent is and what it does. Save the file. That is an agent.

Keep it small and single purpose. One agent sorts the inbox. One answers the support line. One checks the servers at 3 a.m. and only wakes you if something is wrong.

Each one wakes up when something happens: a time on the clock, an email, a text, a message on a socket. Every one of those triggers is already in the box.

A new kind of software

AI Project Portfolio Management.

The first project teaches you the box. By the tenth, you are mostly snapping together parts you already have.

Every project you finish leaves new parts behind: a connector to your billing system, a report your team likes, an agent that knows your customers. They go back in the box. You never build them twice.

10
Safe by construction

No npm install. No pip install. Ever.

Every component ships inside one binary. Nothing downloads code onto your machine while you build or while your app runs.

Your agent cannot pull in a bad package by mistake, because it never needs a package. What is on your computer is what you chose to put there.

When you finish, luca bundle turns your project into its own binary. The people who run it do not install Luca, Bun, or anything else.

Read this before you build. The box is opinionated on purpose. The components decide how data is stored, how servers talk, and how agents are wired. That is the constraint that makes it safe and makes a $20 model good enough.
