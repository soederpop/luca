Everything in the box. Each component has a standard shape, its own instructions, and one place to find it: the container.

glue three components together 
const db = container.feature('sqlite', { path: 'bookings.db' })
const scheduler = container.feature('scheduler')
const telegram = container.feature('telegram')

// every weekday at 8, text the owner today's bookings
scheduler.cron('0 8 * * mon-fri', async () => {
  const today = await db.query(
    'SELECT name, time FROM bookings WHERE day = date()'
  )
  await telegram.bot.api.sendMessage(
    process.env.OWNER_CHAT, `${today.length} bookings today`
  )
}, { name: 'morning-digest' })

await scheduler.run()

How the parts work

Same shape. Every time.

Every component is made the same way. Learn one and you know how to hold all of them.

Each has options checked by a schema, observable state, and events other components can listen to. Each describes itself, so a person or an agent can ask what it does, what it needs, and how to use it.

Every one is tested, documented, security checked, and tuned before it goes in the box. Your agent builds on parts that already work, instead of code it wrote five minutes ago.

Need a part that is not in the box? Make one. Yours gets the same shape and the same standards, and goes back in the box for your next project.

# read the docs for any component
luca describe telegram
luca describe sqlite.query

# make your own component
luca scaffold feature billing --description "Talks to our billing system"

A few components are marked experimental. They work, and their shape may still change.

The catalog needs JavaScript. Run luca describe features for the same list.

All of it ships in one binary.

Nothing to install from npm or pip. Get the CLI and the whole catalog comes with it.

curl -fsSL https://luca-js.soederpop.com/install.sh | bash
