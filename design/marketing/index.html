Give the on-call agent
access to the machine.

Search the Markdown runbooks, inspect a failing service over SSH, delegate a fix to a coding agent, and evaluate the result in the same running process.

Target environment
SSH: staging-api
Workspace: ./services/api
  • contentDbMarkdown brain
  • secureShellRemote execution
  • claudeCodeCoding sessions
  • vmLive evaluation
harnesses/infrastructure.ts 
import container from 'luca'

const operator = container.feature('assistant', {
  systemPrompt: `You operate the staging API.
    Search the runbooks first. Inspect the service and delegate
    a patch with coder.run() through evalCode.
    Verify the result before reporting back.`,
})

operator.use(container.feature('contentDb', {
  rootPath: './brain',
}))
operator.use(container.feature('secureShell', {
  host: 'staging-api',
}))
container.addContext('coder', container.feature('claudeCode', {
  cwd: container.paths.resolve('services/api'),
}))
operator.use(container.feature('vm'))

await operator.start()
await operator.ask(
  'Investigate the failing health check on staging-api.'
)
Requires a configured model provider, ./brain collection, SSH alias, and Claude Code CLI.

One binary.
That builds your binaries.

Luca is the toolkit you install. The tool you ship is yours: your commands, features, endpoints, and assistant definitions, compiled with the runtime into a standalone executable. Give your team a database analyst, an operations agent, or a coding supervisor they can run as a single file.

Build for macOS or Linux with Bun on your build machine. Recipients run the compiled tool without installing Luca or Bun, using their configured model providers and external services. 

# From your Luca project
luca bundle ops-agent \
  --targets darwin-arm64,linux-x64

# Your runtime, tools, and assistants inside
./dist/ops-agent-darwin-arm64 --help
