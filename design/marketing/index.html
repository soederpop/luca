One binary. A TypeScript SDK for AI-native software.

Build the system.
Put an agent inside it.

Luca is a single binary that builds any application architecture: HTTP APIs, WebSocket services, CLIs, MCP servers, phone lines, terminal and browser UIs. Assistants are first-class parts of that runtime. They use the same tools, state, and events as your code, answer over any transport you give them, and can inspect, extend, and rebuild the system they run in. Then compile all of it into a binary of your own.

Every architecture.
One runtime.

The container is a dependency injector, event bus, and state machine in one process. Endpoints mount themselves and generate their own OpenAPI docs. Commands become a CLI. Selectors cache queries. Ink renders terminal UIs. State and events are shared by every part, including the assistants.

Imagine your API starts failing.

The service, its state, and the tools to inspect it are already one object graph. There is nothing to wire together at three in the morning. 

const api = container.server('express')   // endpoints/ mount themselves
api.serveOpenAPISpec()                     // docs generated from the routes
container.state.set('incident', { service: 'api', since: Date.now() })
02 / 08

An operator.
Not a chat box.

An assistant is a folder: CORE.md for the prompt, tools.ts for typed tools, hooks.ts for lifecycle. It is a feature like any other, so it shares the container’s state and events. Call use() on any helper and that helper’s tools become the assistant’s tools, with the operating notes it needs already in its prompt. Memory, a skills library, an MCP bridge, and the coding agents live on this tray too.

Hand the failure to the operator.

It calls the functions your code calls, and answers through whatever interface you build: an HTTP route, a socket, an MCP tool, a Telegram bot, a phone call. 

const operator = container.feature('assistant', {
  folder: 'assistants/operator',   // CORE.md + tools.ts + hooks.ts
})
operator.use(container.feature('memory'))
operator.use(container.feature('mcpBridge', { servers }))
03 / 08

Your Markdown
becomes its memory.

A folder of Markdown with frontmatter becomes a typed, queryable database through Contentbase. Semantic search finds the right runbook. Beside it sit SQLite, Postgres, Redis, a locked cross-process store, and a disk cache, each with typed tools the assistant can call.

Find the procedure before touching anything.

The operator reads past incidents and deployment notes to learn what failed and how your team handles it. Your decisions become its defaults. 

operator.use(container.feature('contentDb', { rootPath: './brain' }))
operator.use(container.feature('postgres', { url, readOnly: true }))
operator.use(container.feature('skillsLibrary'))
04 / 08

Real tools.
Real machines.

Files, ripgrep, child processes, long-running process management, SSH and SCP, tmux sessions, Docker, and git. Each helper ships typed tools and prompt guidance, so attaching one also teaches the assistant how to use it safely.

Inspect the machine that is failing.

Attach SSH for remote diagnostics. Read the logs, check the container, look at the last commit. The same tray runs a deployment agent or a repo maintainer. 

operator.use(container.feature('secureShell', { host: 'staging-api' }))
operator.use(container.feature('docker'))
operator.use(container.feature('git'))

Google Workspace, Telnyx telephony, Telegram, browser automation, text to speech, screen capture, a scheduler for cron and intervals, and a vault for secrets. The same architecture runs an infrastructure operator or an assistant with its own phone number.

Tell the humans.

Post the diagnosis to the on-call channel, or call the engineer on duty. Pull the incident doc from Drive. A different job would schedule itself to run every night instead.

Speak every
protocol.

REST that returns parsed JSON and hands back errors as values. WebSocket and Socket.IO with correlated ask() and reply(). Unix-socket IPC between processes. GraphQL. An OpenAI-compatible client that reaches any model server. ContainerLink, which lets one container evaluate code in another. Speech in and out.

Query the upstream.

The operator asks the payment provider’s API what changed, and asks a browser container what the user actually sees. 

const upstream = container.client('rest', { baseURL })
const status = await upstream.get('/status')   // parsed JSON, no unwrap
const ws = container.client('websocket', { baseURL: wsURL })
const reply = await ws.ask('getUser', { id })
07 / 08

Serve the operator
to everyone.

Express with auto-mounted endpoints. A WebSocket server that bridges to the event bus. IPC over Unix sockets. An MCP server that turns any helper or assistant into tools for Claude Code, Codex, or Cursor. An LLM proxy that fronts local and paid models behind one OpenAI-compatible URL.

Expose the operator.

Your team’s coding agents get it as an MCP tool. The dashboard gets it over a socket. Another process gets it over IPC. One assistant, no copies. 

const mcp = container.server('mcp', { serverName: 'operator' })
mcp.tool('ask', { schema, handler: ({ question }) => operator.ask(question) })
await mcp.start()   // or: luca mcp --assistant operator
08 / 08

It can rebuild
the system it runs in.

Every command, endpoint, script, and snippet runs through the VM, which is why a folder of TypeScript needs no install step. Give that VM to the assistant and it runs TypeScript inside its own live process: the real container, every helper in scope, the runtime’s docs one call away. It can delegate to Claude Code, Codex, or Hermes, fork itself, create and test other assistants, write new tools and skills, and compile a fresh binary of itself.

From diagnosis to a verified fix.

Delegate a patch to a coding agent, read the diff, run the tests, then report. Then write the runbook and a new tool so next time takes one call. 

operator.use(container.feature('vm'))                 // live TypeScript, real process
operator.use(container.feature('assistantsManager'))  // create, edit, test assistants
await operator.start()
await operator.ask('Fix the failing API. Verify it. Write the runbook.')

access to the machine.

Search the Markdown runbooks, inspect a failing service over SSH, delegate a fix to a coding agent, and verify the result from inside the same running process.

Workspace: ./services/api

harnesses/infrastructure.ts 
import container from 'luca'

const operator = container.feature('assistant', {
  systemPrompt: `You operate the staging API.
    Search the runbooks first. Inspect the service and delegate
    a patch with coder.run() through evalCode.
    Verify the result before reporting back.`,
})

operator.use(container.feature('contentDb', {
  rootPath: './brain',
}))
operator.use(container.feature('secureShell', {
  host: 'staging-api',
}))
container.addContext('coder', container.feature('claudeCode', {
  cwd: container.paths.resolve('services/api'),
}))
operator.use(container.feature('vm'))

await operator.start()
await operator.ask(
  'Investigate the failing health check on staging-api.'
)

One binary
that builds your binaries.

Luca is the toolkit you install. What you ship is yours: your commands, features, endpoints, and assistants, compiled with the runtime into one executable. Hand your team a database analyst, an operations agent, or a coding supervisor as a single file. An assistant with the VM can run this step too, and ship a new version of itself.

Build for macOS or Linux with Bun on the build machine. Recipients run the compiled tool with no Luca, no Bun, and no node_modules, using their own model providers and services. Keep eval and describe in the build and the binary can still introspect itself. 

# From your Luca project
luca bundle ops-agent \
  --targets darwin-arm64,linux-x64 \
  --builtins eval,describe

# Your runtime, tools, and assistants inside
./dist/ops-agent-darwin-arm64 --help
./dist/ops-agent-darwin-arm64 chat operator
